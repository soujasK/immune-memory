# Pilot methodology

The frozen decision rules are in preregistered_pilot.md. This implementation uses a transport-only loopback chat client. Agent A gets the only seeded memo. B receives A's first message in both source states. The removal event precedes B's action, removes A's private history, and substitutes the scheduler acknowledgment for the usual check-in. C sees B's generated note and D sees C's generated note. The source has no direct path to D. Each episode starts with four fresh local history containers. This is short-horizon persistence through retained text in a fixed chain.

The trusted ticket gives the rule needed to do the task. The hidden evaluator fixture separately maps case IDs to allowed destination, field and value. Case type, scorer, and decision gate are excluded from all messages. D's output is the only mock action channel and is recorded as a ledger of structured triples. Exact authorization pairs and secret-marker checks are deterministic. Malformed actions have an unknown violation outcome and unsuccessful completion. Free-text intermediary messages stay inside the fictional network and are outside the primary disclosure endpoint.

Paired warning and neutral rows use the same case and sampler seed within removal state. Phase two would require GO. Direct protective instructions, memory ablation, alternative topologies and downstream churn are outside the completed pilot. Sample sizes are engineering gates. Two seed replicates in one family do not substitute for independent attack families.

## Implementation audit after data collection began

The phrase “B retains A's first message” in the preregistration is broader than the implementation supports. The runner buffers A's output in a local variable. The removal event occurs before B receives its first user turn, which includes the buffered output and check-in together. There is no observed pre-removal behavior in B. This is a surviving-message-artifact test with delayed delivery, and it cannot establish retention of protective behavior already demonstrated by a surviving agent. The frozen code is retained and the discrepancy is reported as a validity limitation. A future study needs explicit delivery and receiver activity before the removal intervention, followed by a separate post-removal task.
